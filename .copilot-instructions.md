# Copilot Instructions

## Pug Class Attribute Style

**Always use the explicit (class="...") syntax for all class attributes in Pug/Jade files in this project.**

- Do not use dot notation for classes (e.g., .foo.bar) unless required for legacy code.
- Example: `div(class="my-class another-class")` is correct.
- This applies to all new and edited Pug/Jade files, including partials and admin views.

This ensures consistency, clarity, and compatibility with future code reviews and automated tools.

## TypeScript

- All source files use TypeScript (`.ts`). Do not create `.js` files for app logic.
- Use `import`/`export` (ES module syntax compiled to CommonJS via `tsconfig.json`).
- Type Express route handlers with `Request`, `Response`, `NextFunction` from `express`.
- Prisma `User` type is extended onto `Express.User` via `src/types/express.d.ts`.
- Run `npm run build` to compile to `dist/`. Run `npm run dev` for development with `ts-node`.

## Authentication

- Authentication uses Passport.js with Local strategy (email + password) and JWT strategy (httpOnly cookie).
- JWT tokens are stored in httpOnly cookies named `token` (not Authorization header, not localStorage).
- Passport strategies are defined in `src/auth/` and wired together in `src/auth/passport.ts`.
- `middleware/authentication.ts` uses Passport JWT to silently attach `req.user` on every request.
- `middleware/authorization.ts` provides `requireAuth` and `requireRole` guards for route protection.
- Admin routes (`/admin/*`) use `requireRole('admin')` middleware applied in `app.ts`.
- No Passport sessions are used; authentication is fully stateless via JWT.
- `res.locals.user` is set globally in `app.ts` so all Pug views can access `user` without explicit passing.
- Zod validation runs before Passport authentication on login and register routes.
- No client-side JavaScript is used for authentication — all auth flows use standard form POST and page redirects.
